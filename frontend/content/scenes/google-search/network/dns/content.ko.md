# DNS 이름 확인

## 개요

DNS는 계층적인 이름 공간과 resource record를 여러 이름 서버에 분산해 관리합니다. 애플리케이션은 보통 resolver에 이름 확인을 요청하며, resolver는 cache를 확인하거나 이름 서버에 하나 이상의 질의를 보냅니다.

## 필요한 이유

서비스 이름은 사람이 읽고 운영 정책에 따라 변경하기 쉽지만, IP packet을 전달하려면 목적지 주소가 필요합니다. DNS는 이름과 주소를 포함한 여러 종류의 정보를 분리된 관리 영역에서 조회할 수 있게 합니다.

## 동작 과정

1. 애플리케이션이 resolver에 이름과 필요한 record type을 전달합니다.
2. Resolver가 유효한 cache 응답이 있는지 확인할 수 있습니다.
3. Cache로 해결되지 않으면 resolver가 이름 서버에 질의를 보냅니다.
4. 이름 서버는 최종 답이나 다른 이름 서버를 가리키는 referral을 반환할 수 있습니다.
5. Resolver가 결과를 애플리케이션에 돌려줍니다.

## 내부 구조

RFC 1034가 설명하는 일반 구조에서는 사용자 프로그램이 모든 이름 서버를 직접 순회하기보다 resolver가 질의 과정을 담당합니다. 이 학습 경로에서는 DNS 메시지가 UDP datagram으로 전달되는 경우를 다음 Topic으로 제공합니다.

## 실패 상황

- 응답이 시간 안에 도착하지 않아 재시도가 필요할 수 있습니다.
- 이름이 존재하지 않는다는 응답을 받을 수 있습니다.
- 오래되거나 잘못된 cache 정보 때문에 기대하지 않은 주소를 사용할 수 있습니다.
- UDP 응답이 잘리거나 사용 조건에 맞지 않아 TCP 같은 다른 전송 방식이 필요할 수 있습니다.

## 실무 맥락

장애를 확인할 때는 애플리케이션 설정, 로컬 resolver, cache 상태와 권한 있는 이름 서버를 구분해야 합니다. 하나의 도구에서 응답을 받았다는 사실만으로 모든 사용자의 resolver 경로가 정상이라고 단정할 수 없습니다.

## 관련 개념

DNS는 UDP와 TCP를 모두 사용할 수 있습니다. 현재 지도는 일반적인 UDP 질의를 먼저 확대하지만, 모든 DNS 통신이 항상 UDP만 사용된다는 의미는 아닙니다.
