# 한눈에 보기

Starvation은 여러 스레드가 자원을 두고 경쟁할 때 `특정 스레드`가 `지속적으로 자원을 획득하지 못해` 작업을 진행하지 못하는 상태입니다.
주로 `불공정한 Lock 획득`이나 자원 할당으로 인해 발생하며, Deadlock과 달리 `다른 스레드들의 작업은 계속 진행`됩니다.
이를 방지하기 위해 공정한 Lock을 사용하거나 Lock 점유 시간을 줄이고, 자원 획득 기회를 적절하게 분배해야 합니다.

---

# Starvation이란?

Starvation은 여러 스레드가 공유 자원을 두고 경쟁하는 과정에서, `특정 스레드`가 `지속적으로 자원을 획득하지 못해` 작업을 진행하지 못하는 상태를 의미합니다.
다른 스레드들은 정상적으로 작업을 수행하지만, 특정 스레드만 자원 획득 기회를 얻지 못한다는 특징이 있습니다.
Deadlock이 여러 스레드가 서로를 기다리며 작업을 진행하지 못하는 상태라면, Starvation은 다른 스레드들의 작업은 진행되지만 특정 스레드만 계속 대기한다는 차이가 있습니다.

---

# Starvation의 발생 원인

Starvation은 특정 스레드가 공유 자원을 장시간 독점하거나, 자원 `획득 기회가 불공정하게 분배`될 때 발생할 수 있습니다.
다음은 한 스레드가 Lock을 계속 점유하여 다른 스레드가 작업을 진행하지 못하는 예시입니다.

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Object lock = new Object();

        synchronized (lock) {
            new Thread(() -> {
                synchronized (lock) {
                    System.out.println("Thread 2 작업 완료");
                }
            }).start();

            Thread.sleep(Long.MAX_VALUE); // Lock 장기 점유
        }
    }
}
```

1. Main 스레드는 Lock을 획득한 상태에서 장시간 대기합니다.
2. Thread 2는 동일한 Lock을 획득하려 하지만 진입하지 못합니다.
3. Main 스레드가 Lock을 해제하지 않는 동안 Thread 2는 작업을 진행할 수 없습니다.

이 예시는 자원 독점으로 인해 다른 스레드의 진행이 무기한 지연되는 상황을 단순화한 것입니다. 의도적으로 종료되지 않도록 작성했습니다.
다만 Starvation의 대표적인 원인은 단순히 Lock을 오래 점유하는 것뿐 아니라, 다른 스레드들은 계속 자원을 획득하는데 특정 스레드만 `반복적으로 기회를 얻지 못하는 불공정성`입니다.

# Starvation을 해결하는 방법

Starvation을 방지하려면 특정 스레드가 자원 획득 기회를 지속적으로 박탈당하지 않도록 설계해야 합니다.

## 공정한 Lock 사용

ReentrantLock은 공정성 옵션을 제공하며, 이를 통해 오랫동안 `기다린 스레드`가 우선적으로 `Lock을 획득`하도록 할 수 있습니다.

앞선 예시에서 Lock 생성 부분을 다음과 같이 변경할 수 있습니다.

```java
static final ReentrantLock lock = new ReentrantLock(true);
```

공정한 ReentrantLock은 여러 스레드가 Lock을 기다릴 때 대체로 먼저 대기한 스레드에 획득 기회를 제공합니다.
이를 통해 특정 스레드가 반복적으로 Lock 획득에서 밀리는 상황을 줄일 수 있습니다.

다만 공정한 Lock은 스레드의 대기 및 전환 비용으로 인해 처리량이 감소할 수 있으며, 스레드 스케줄링까지 공정하게 보장하는 것은 아닙니다.

## Lock 점유 시간 최소화

특정 스레드가 Lock을 오랫동안 점유하면 다른 스레드의 대기 시간이 길어질 수 있습니다.
따라서 `Lock이 필요한 작업만 임계 영역에 포함`하고, 불필요한 작업은 Lock 외부에서 수행하도록 설계해야 합니다.

이는 Lock 경쟁과 대기 시간을 줄이는 데 도움이 되지만, 그 자체로 공정한 획득 순서를 보장하지는 않습니다.
