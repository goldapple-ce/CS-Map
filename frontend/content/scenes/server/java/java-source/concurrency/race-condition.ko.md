# 한눈에 보기

Race Condition은 `여러 스레드`가 `공유 가변 상태에 접근`할 때, 스레드의 실행 순서에 따라 의도하지 않은 결과가 발생할 수 있는 `동시성 문제`를 의미합니다.
대표적으로 원자성이 보장되지 않는 복합 연산에서 `Lost Update`가 발생할 수 있으며, 이를 방지하려면 `Critical Section`을 식별하고 적절한 동시성 제어를 적용해야 합니다.
Data Race와는 달리 개별 메모리 접근이 동기화되어 있어도 발생할 수 있으며, 두 개념은 각각 논리적 정확성과 메모리 접근의 동기화 여부에 초점을 둡니다.

---

# Race Condition이란?

Race Condition은 `여러 스레드`가 `공유 가변 상태에 접근`할 때, 스레드의 실행 순서에 따라 의도하지 않은 결과가 발생할 수 있는 `동시성 문제`를 의미합니다.
여러 스레드가 공유 자원을 읽거나 변경하는 과정에서 `작업이 서로 간섭`하면, 데이터의 일관성이 깨지거나 예상하지 못한 결과가 발생할 수 있습니다.

---

# Race Condition의 발생 원인

Race Condition은 여러 스레드가 공유 가변 상태에 접근하는 과정에서 `연산의 실행 순서가 적절하게 제어되지 않을 때` 발생할 수 있습니다.
다음은 공유 변수의 값을 증가시키는 예시입니다.

```
class Counter {
    private int count = 0;

    void increment() {
        count++;
    }
}
```

count++는 하나의 연산처럼 보이지만 실제로는 다음 과정으로 이루어집니다.

1. Read: 공유 변수의 현재 값을 읽습니다.
2. Modify: 읽은 값에 1을 더합니다.
3. Write: 변경된 값을 공유 변수에 저장합니다.

두 스레드가 count가 0인 상태에서 증가 연산을 수행한다고 가정해 봅시다.

| 순서 | Thread 1  | Thread 2  |
| ---- | --------- | --------- |
| 1    | Read: 0   |           |
| 2    |           | Read: 0   |
| 3    | Modify: 1 |           |
| 4    |           | Modify: 1 |
| 5    | Write: 1  |           |
| 6    |           | Write: 1  |

두 스레드가 동일한 값을 읽고 각각 증가시킨 결과를 저장하면서, 한 스레드의 변경이 다른 스레드의 변경에 의해 덮어써지는 `Lost Update`가 발생합니다.
이처럼 복합 연산의 원자성이 보장되지 않으면 스레드의 실행 순서에 따라 결과가 달라질 수 있습니다.

---

# Critical Section

임계 영역(Critical Section)이란 여러 스레드가 `공유 자원에 접근하는 코드 영역` 중, 동시 실행으로 인해 `Race Condition`이 발생할 수 있어 `동기화가 필요한 영역`을 의미합니다.
앞서 살펴본 count++가 대표적인 예시입니다.

```
void increment() {
    count++; // 임계 영역
}
```

따라서 Race Condition을 방지하려면 이러한 코드 영역을 식별하고 적절한 동시성 제어를 적용해야 합니다.

---

# Race Condition을 해결하는 방법

Race Condition을 방지하려면 공유 가변 상태에 대한 여러 스레드의 작업이 서로 간섭하지 않도록 제어해야 합니다.
Java에서는 대표적으로 다음과 같은 방법을 사용할 수 있습니다.

- `Lock-based`: 상호 배제를 보장하고 임계 영역의 동시 실행을 제한합니다.
- `Lock-Free`: 원자적 연산을 활용하여 Lock 없이 공유 상태를 안전하게 갱신합니다.
- `공유 가변 상태 최소화`: 불변 객체나 ThreadLocal 등을 활용하여 스레드 간 공유 상태를 줄이거나 격리합니다.

Lock-based는 상호 배제를 통해 임계 영역을 보호하는 방식이며, Lock-Free는 동시 접근을 허용하면서 원자적 연산으로 데이터의 일관성을 유지하는 방식입니다.

# Race Condition과 Data Race의 차이

Race Condition과 Data Race는 모두 여러 스레드의 공유 자원 접근과 관련이 있지만, 서로 다른 관점의 문제입니다.

- `Race Condition`: 스레드의 실행 순서에 따라 프로그램의 논리적 결과가 달라지는 문제입니다.
- `Data Race`: 서로 다른 스레드가 동일한 변수에 접근하고, 적어도 하나가 쓰기 연산이며, 두 접근 사이에 Happens-Before 관계가 없는 상황입니다.

앞서 살펴본 count++ 예시는 Race Condition과 Data Race가 함께 발생할 수 있는 사례입니다.
하지만 Data Race가 발생하지 않더라도 Race Condition은 발생할 수 있습니다.
다음은 AtomicInteger를 활용한 예시입니다.

```
AtomicInteger count = new AtomicInteger(9);

void increment() {
    if (count.get() < 10) {
        count.incrementAndGet();
    }
}
```

AtomicInteger의 개별 연산은 원자성과 필요한 메모리 동기화를 보장하므로 Data Race는 발생하지 않습니다.
하지만 두 스레드가 모두 count가 9인 것을 확인하고 값을 증가시키면 최종 값이 11이 될 수 있습니다.
이는 개별 연산이 원자적으로 수행되더라도 조건 확인과 값 변경으로 구성된 전체 작업의 원자성까지 보장되는 것은 아니기 때문입니다.
즉, `Race Condition`은 작업의 `실행 순서와 논리적 정확성에 초점`을 두며, `Data Race`는 `공유 메모리 접근의 동기화 여부`에 초점을 둡니다.
