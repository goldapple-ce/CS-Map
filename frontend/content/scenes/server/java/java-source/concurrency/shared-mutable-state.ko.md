멀티스레드 환경에서 공유 가변 상태에 대한 접근이 적절하게 조정되지 않으면 Race Condition이나 Data Race가 발생할 수 있습니다.
이를 예방하기 위해 ThreadLocal로 공유를 줄이거나 Immutability로 가변성을 제거할 수 있으며, 필요한 공유 가변 상태는 적절한 동시성 제어가 필요합니다.

---

# 공유 가변 상태란?

공유 가변 상태는 `여러 스레드`가 동일한 데이터에 `접근`할 수 있으며, 해당 데이터의 `상태가 변경`될 수 있는 것을 의미합니다.

공유 가변 상태는 다음 두 가지 특성을 가집니다.

1. `공유성`: 여러 스레드가 동일한 데이터에 접근할 수 있습니다.
2. `가변성`: 해당 데이터의 상태를 변경할 수 있습니다.

Java에서는 여러 스레드가 동일한 객체를 참조하면 해당 객체의 인스턴스 필드가 공유될 수 있으며, static 필드 역시 여러 스레드에서 접근할 수 있습니다.
반면 각 스레드가 독립적인 객체를 생성하여 사용한다면, 객체가 가변적이더라도 공유 가변 상태에 해당하지 않습니다.

---

# 공유 가변 상태와 동시성 문제

공유 가변 상태 자체가 동시성 문제를 발생시키는 것은 아닙니다.
하지만 멀티스레드 환경에서 여러 스레드가 공유 가변 상태에 접근하면 실행 순서나 동기화 여부에 따라 문제가 발생할 수 있습니다.

- `Race Condition`: 여러 스레드의 실행 순서에 따라 의도하지 않은 결과가 발생하는 문제입니다.
- `Data Race`: 동일한 변수에 대한 충돌하는 접근 사이에 Happens-Before 관계가 없는 상황입니다.

따라서 멀티스레드와 공유 가변 상태는 Race Condition과 Data Race를 이해하기 위한 핵심적인 연결점입니다.

---

## 공유 가변 상태 최소화

동시성 문제를 예방하는 방법 중 하나는 `공유할 필요가 없는 상태`를 격리하거나, 공유 객체의 `가변성을 제거`하는 것입니다.

대표적으로 ThreadLocal과 Immutability를 활용할 수 있습니다.

- `ThreadLocal`: 스레드마다 독립적인 값을 저장하여 불필요한 공유 가변 상태를 격리합니다. Thread Confinement를 구현하는 방법 중 하나입니다.
- `Immutability`: 객체 생성 이후 상태를 변경할 수 없도록 하여, 여러 스레드가 동일한 객체를 공유하더라도 상태 변경으로 인한 충돌이 발생하지 않도록 합니다.

ThreadLocal은 `공유를 줄이는 방식`이고, Immutability는 `가변성을 제거하는 방식`입니다.

다만 여러 스레드가 동일한 데이터를 함께 변경해야 하는 경우에는 공유 가변 상태를 제거할 수 없습니다.
이러한 경우 Lock-Based나 Lock-Free와 같은 동시성 제어 방법을 통해 공유 상태를 안전하게 관리해야 합니다.
