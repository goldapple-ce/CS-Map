# 한눈에 보기

Concurrency는 여러 작업이 시간적으로 겹쳐 진행될 수 있도록 구성하는 것으로, 컴퓨팅 자원의 활용도와 시스템의 응답성을 높이는 데 활용됩니다.
공유 가변 상태에 대한 동시 접근으로 Race Condition이나 Data Race가 발생할 수 있으며, 이를 방지하기 위해 Thread Safety를 확보해야 합니다.
또한 데이터의 안전성뿐 아니라 Deadlock, Livelock, Starvation과 같은 작업 진행 문제도 함께 고려해야 합니다.

---

# Concurrency란?

동시성(Concurrency)은 여러 작업이 시간적으로 겹쳐 진행될 수 있도록 구성하는 것을 의미합니다.
하나의 CPU 코어에서 여러 작업을 번갈아 실행하거나, 여러 CPU 코어에서 작업을 동시에 실행하는 방식으로 구현할 수 있습니다.

---

# 동시성이 필요한 이유

동시성은 컴퓨팅 자원을 효율적으로 활용하고, 여러 작업을 독립적으로 처리하기 위해 필요합니다.
예를 들어 서버는 여러 사용자의 요청을 처리해야 하며, 특정 작업이 입출력을 기다리는 동안 다른 작업을 수행할 수 있어야 합니다.

Java에서는 멀티스레드 등의 방법으로 동시성을 구현하여 시스템의 처리량과 응답성을 개선할 수 있습니다.

---

# 동시성으로 인해 발생하는 문제

여러 작업이 동시에 진행되면 각 작업의 실행 순서와 타이밍을 예측하기 어려워집니다.
특히 여러 스레드가 공유 가변 상태에 접근하는 환경에서는 다음과 같은 문제가 발생할 수 있습니다.

- `Race Condition`: 스레드의 실행 순서에 따라 의도하지 않은 결과가 발생하는 문제입니다.
- `Data Race`: 동일한 변수에 대한 충돌하는 접근 사이에 Happens-Before 관계가 없는 상황입니다.

Race Condition은 작업의 논리적 정확성에 초점을 두며, Data Race는 공유 메모리 접근의 동기화 여부에 초점을 둡니다.

이러한 문제를 이해하기 위해서는 원자성뿐 아니라 스레드 간 메모리 가시성과 실행 순서도 고려해야 합니다.
Java에서는 이러한 메모리 동작과 동기화의 보장 규칙을 JMM을 통해 정의합니다.

---

# Thread Safety

Thread Safety는 여러 스레드가 동일한 객체나 공유 자원에 동시에 접근하더라도 `데이터의 일관성을 유지하고 올바르게 동작하는 특성`을 의미합니다.

Thread Safety는 특정 동기화 기술이 아니라, 동시성 환경에서 객체나 시스템이 갖추어야 할 안전성에 관한 특성입니다.

중요한 것은 `개별 연산의 스레드 안전성이 여러 연산을 조합한 전체 작업의 안전성까지 보장하지는 않는다`는 점입니다.
예를 들어 AtomicInteger는 개별 연산의 원자성을 보장하지만, 조건을 확인한 뒤 값을 변경하는 Check-Then-Act 작업에서는 Race Condition이 발생할 수 있습니다.

따라서 Thread Safety를 확보하려면 개별 연산뿐 아니라 여러 연산으로 구성된 작업의 논리적 정확성까지 고려해야 합니다.

---

# Thread Safety를 확보하는 방법

Java에서는 공유 가변 상태를 안전하게 제어하거나, 공유 및 상태 변경 자체를 줄이는 방식으로 Thread Safety를 확보할 수 있습니다.

1. `Lock-Based`: synchronized, ReentrantLock 등을 이용한 상호 배제로 공유 자원에 대한 동시 접근을 제어합니다.
2. `Lock-Free`: CAS와 같은 원자적 연산을 활용하여 Lock 없이 공유 상태를 안전하게 갱신합니다.
3. `Immutability`: 객체의 상태 변경을 제한하여 여러 스레드가 동일한 객체를 안전하게 공유하도록 합니다.
4. `ThreadLocal`: 스레드마다 독립적인 상태를 유지하여 불필요한 공유 가변 상태를 격리합니다.

Lock-Based와 Lock-Free는 공유 가변 상태에 대한 접근을 제어하는 방식입니다.
반면 Immutability와 ThreadLocal은 상태 변경이나 공유 자체를 줄여 동시성 문제를 예방하는 방식입니다.

따라서 Thread Safety를 확보하기 위해 반드시 Lock을 사용해야 하는 것은 아니며, 공유 자원의 특성에 따라 적절한 방법을 선택해야 합니다.

---

# 동시성 제어에서 발생하는 문제

공유 데이터의 안전성을 확보하더라도 모든 동시성 문제가 해결되는 것은 아닙니다.
동기화 과정에서 스레드가 작업을 정상적으로 진행하지 못하는 문제가 발생할 수 있습니다.

- `Deadlock`: 여러 스레드가 서로 상대방이 점유한 자원을 기다리면서 작업을 진행하지 못하는 상태입니다.
- `Livelock`: 스레드들이 계속 상태를 변경하지만 실질적인 작업은 진행하지 못하는 상태입니다.
- `Starvation`: 다른 스레드는 작업을 진행하지만 특정 스레드가 지속적으로 자원 획득 기회를 얻지 못하는 상태입니다.

따라서 동시성 환경에서는 `데이터의 안전성`뿐 아니라 `작업의 진행 가능성`도 함께 고려해야 합니다.
