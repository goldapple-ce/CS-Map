# 한눈에 보기

Livelock은 여러 스레드가 서로의 행동에 반응하여 계속 `상태를 변경`하지만 `실제 작업은 진행하지 못하는 상태`입니다.
Deadlock과 달리 `스레드가 멈춰 있지 않으며`, 반복적인 양보나 재시도로 인해 발생할 수 있습니다.
이를 방지하기 위해 우선순위를 부여하거나 재시도 시점에 차이를 두고, 재시도 횟수를 제한하는 방법 등을 활용할 수 있습니다.

---

# Livelock이란?

Livelock은 여러 스레드가 서로의 작업에 반응하여 계속 `상태를 변경`하지만, `실제 작업은 진행하지 못하는 상태`를 의미합니다.
Deadlock은 스레드들이 서로 자원을 기다리며 멈춰 있는 반면, Livelock은 스레드들이 계속 실행되면서도 작업을 완료하지 못한다는 차이가 있습니다.

---

# Livelock의 발생 원리

Livelock은 여러 스레드가 충돌을 피하기 위해 양보하거나 재시도하는 과정에서, `서로의 행동에 반복적으로 반응`할 때 발생할 수 있습니다.
예를 들어 두 사람이 좁은 복도에서 마주쳤을 때, 서로 길을 비켜주려다가 계속 같은 방향으로 움직여 지나가지 못하는 상황과 유사합니다.
다음은 두 스레드가 자신의 차례를 상대방에게 계속 양보하는 예시입니다.

```java
public class Main {
    static String turn = "A";

    static synchronized boolean yieldTurn(String me, String other) {
        if (!turn.equals(me)) return false;

        turn = other; // 상대방에게 양보
        return true;
    }

    public static void main(String[] args) {
        Runnable a = () -> work("A", "B");
        Runnable b = () -> work("B", "A");

        new Thread(a).start();
        new Thread(b).start();
    }

    static void work(String me, String other) {
        int count = 0;
        while (count < 3) {
            if (yieldTurn(me, other)) {
                System.out.println(me + " 양보");
                count++;
            }
            Thread.yield();
        }
    }
}
```

위 코드는 무한 반복을 피하기 위해 양보 횟수를 3회로 제한한 예시입니다.

1. Thread A는 자신의 차례가 되면 Thread B에게 양보합니다.
2. Thread B 역시 자신의 차례가 되면 Thread A에게 양보합니다.
3. 두 스레드는 계속 차례를 주고받지만, 실제 작업은 수행하지 못합니다.

이처럼 스레드가 멈춰 있는 것이 아니라 `상태를 계속 변경하면서도 작업의 진전이 없는 것`이 Livelock의 핵심입니다.

# Livelock을 해결하는 방법

Livelock을 방지하려면 여러 스레드가 동일한 방식으로 양보하거나 재시도하는 상황을 피해야 합니다. 대표적인 방법은 다음과 같습니다.

- `우선순위 부여`: 충돌이 발생하면 정해진 기준에 따라 특정 스레드가 먼저 작업하도록 합니다.
- `무작위 대기`: 재시도 시점에 차이를 두어 반복적인 충돌을 줄입니다.
- `재시도 제한`: 반복 횟수나 시간을 제한하고, 실패 시 다른 처리 방법으로 전환합니다.

## 우선순위 부여

충돌이 발생했을 때 모든 스레드가 서로 양보하는 대신, `일정한 기준에 따라 작업 순서를 결정`하는 방법입니다.
앞선 예시에서 Thread A가 우선적으로 작업을 수행하고, Thread B는 A의 작업이 끝난 후 실행하도록 구성하면 반복적인 양보를 방지할 수 있습니다.

## 무작위 대기

여러 스레드가 동일한 시점에 작업을 재시도하면 충돌이 반복될 수 있습니다.
따라서 재시도 전에 무작위 시간만큼 대기하도록 하여 `스레드들의 재시도 시점이 겹칠 가능성을 줄일 수 있습니다.`

ReentrantLock의 `tryLock()`을 활용하는 알고리즘에서 Lock 획득에 실패하면 기존 Lock을 해제하고, 서로 다른 시간 동안 대기한 후 재시도하는 방식이 대표적입니다.
다만 무작위 대기는 충돌 가능성을 낮추는 방법이며, 작업 완료를 반드시 보장하지는 않습니다.

## 재시도 제한

스레드가 반복적으로 작업에 실패한다면 무한히 재시도하는 대신, `재시도 횟수나 제한 시간을 설정`할 수 있습니다.
정해진 횟수 내에 작업을 완료하지 못하면 실패를 반환하거나 다른 처리 방식으로 전환하여, 진행되지 않는 작업에 자원이 계속 소비되는 상황을 방지합니다.
다만 재시도 제한 자체가 작업의 성공을 보장하는 것은 아닙니다.
