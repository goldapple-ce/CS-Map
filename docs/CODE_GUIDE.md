# 코드 작성 가이드

Frontend 코드를 추가하거나 수정할 때 따르는 공통 규칙이다. 애플리케이션 구조는 [아키텍처](./ARCHITECTURE.md)를 따른다.

## 작성 전 확인

- 수정할 코드와 이를 사용하는 위치를 먼저 확인한다.
- 기존 구조와 작성 방식을 파악한 뒤 같은 방식으로 구현한다.
- 현재 작업과 관계없는 코드는 함께 정리하거나 리팩터링하지 않는다.

## 코드 구성

- 콘텐츠 데이터와 화면을 그리는 코드를 분리한다.
- 같은 역할의 기존 컴포넌트와 함수를 우선 재사용한다.
- 한 파일에 여러 책임이 모이면 역할에 따라 분리한다.
- 새 상태를 만들기 전에 기존 상태와 데이터 흐름으로 해결할 수 있는지 확인한다.
- 새로운 라이브러리는 현재 구조로 해결하기 어려울 때만 추가한다.

## 주석

- 이름만으로 역할을 알기 어려운 함수나 메서드는 선언 위에 무엇을 담당하는지 짧게 설명한다.
- 이름이 명확한 단순 함수에는 같은 내용을 반복하는 주석을 달지 않는다.
- 코드 동작을 그대로 읽어 주기보다 코드가 필요한 이유와 주의할 조건을 설명한다.
