# CS Map 요구사항

CS Map이 어떤 제품이며 어떤 경험을 제공해야 하는지 정의한다. 용어는 [프로젝트에서 사용하는 단어](./WORDS.md), 시스템 구조는 [아키텍처](./ARCHITECTURE.md)를 따른다.

## 제품 정의

CS Map은 실제 서비스가 동작하는 과정을 한 화면에서 계속 확대하며, 흩어진 CS 지식이 어디에서 왜 사용되는지 연결해 주는 학습 지도다.

사용자는 개별 CS 개념을 알고 있어도 하나의 요청 안에서 개념이 어디에 등장하고 어떻게 연결되는지 설명하기 어려울 수 있다. CS Map은 과목별 목록 대신 실제 동작 흐름에서 시작해 큰 구조부터 내부 원리까지 탐색하게 한다.

### 대상 사용자

- CS 개념을 학습했지만 개념 사이의 연결이 약한 사람
- 개발 경험은 있으나 요청의 전체 처리 흐름을 설명하기 어려운 사람
- 사용하는 기술의 내부 원리와 시스템상의 위치를 이해하고 싶은 사람

설명은 처음 접하는 개발자도 따라갈 수 있어야 하지만, 컴퓨터와 네트워크의 기초 용어까지 모두 설명하는 입문 과정은 아니다.

### 제품 목표

- 개별 개념을 실제 동작 흐름 안에서 연결한다.
- 소프트웨어에서 운영체제와 하드웨어까지 자연스럽게 깊어지는 탐색을 제공한다.
- 콘텐츠를 추가해도 같은 탐색 방식으로 계속 확장할 수 있게 한다.

### 현재 제공하지 않는 기능

- 회원가입, 사용자 프로필과 학습 진도 저장
- 퀴즈 점수, 결과 저장과 개인화 추천
- 북마크, 댓글과 토론
- 웹 기반 콘텐츠 편집기와 외부 기여 승인 화면
- 모바일에 최적화된 별도 경험
- 전체 지식을 자유롭게 배치하고 이동하는 무한 Canvas

## 제품 원칙

- `카테고리보다 맥락:` 네트워크, OS, DB 같은 고정 과목 메뉴를 기본 탐색으로 사용하지 않는다.
- `큰 것에서 작은 것으로:` 실제 사건의 전체 흐름에서 시작해 클릭으로 세부 내용을 공개한다.
- `페이지 이동보다 확대:` Scene을 교체하지 않고 하나의 World Viewport에서 Camera를 이동한다.
- `깊이 제한 없음:` Scene은 고정된 단계 수 없이 Child Scene을 가질 수 있다.
- `지도와 설명의 역할 분리:` 지도는 위치·관계·흐름을, Explanation Panel은 긴 설명을 보여준다.
- `움직임은 이해를 위해:` 애니메이션은 공간적 관계를 전달하는 데 필요한 만큼만 사용한다.

## 시작 지점

탐색은 다음 질문에서 시작한다.

> 사용자가 브라우저 주소창에 `google.com`을 입력하면 무슨 일이 발생하는가?

Root Scene은 브라우저에서 서버까지 이어지는 전체 흐름을 보여준다. 세부 Topic을 선택하면 DNS, HTTPS, 운영체제, 서버와 데이터 저장소처럼 현재 작성된 Child Scene으로 들어간다.

이 콘텐츠는 일반적인 웹 서비스 구조와 공개적으로 확인된 사실을 설명한다. 공개되지 않은 Google 내부 구현을 아는 것처럼 표현하지 않는다.

## 탐색 요구사항

### 홈페이지와 Explorer

- `/`는 제품 소개, 이용 방법과 Root Scene 미리보기를 제공한다.
- 홈페이지의 Topic을 선택하면 Explorer의 해당 위치로 진입한다.
- Explorer는 탐색하는 동안 하나의 World Viewport를 유지한다.
- 데스크톱에서는 World Viewport와 Explanation Panel을 함께 보여준다.
- 고정된 CS 카테고리 메뉴를 추가하지 않는다.

### Scene 이동

- Child Scene이 있는 Topic을 선택하면 해당 Topic을 중심으로 Camera가 이동하고 확대된다.
- Scene 이동은 전체 페이지 새로고침 없이 이루어진다.
- 사용자는 Root Scene으로 돌아가거나 이전 탐색 위치로 돌아갈 수 있다.
- 뒤로 가기와 앞으로 가기는 이전 Scene, Camera, 선택 Topic과 읽던 위치를 복원한다.
- 모든 게시 Scene은 공유 가능한 URL을 가지며 직접 접근해도 같은 위치가 열린다.
- 다른 Scene으로 이동하는 Topic은 말단 Topic과 시각적으로 구분한다.

### 전체 Topic 목차

- 사용자는 게시된 Topic의 부모·자식 구조와 현재 위치를 확인할 수 있다.
- 목차를 펼치거나 접는 동작은 Camera, URL과 설명을 변경하지 않는다.
- Topic 제목을 검색하고 결과의 상위 경로를 확인할 수 있다.
- 검색 결과를 선택하면 일반 Topic 선택과 같은 방식으로 이동한다.
- 본문과 별칭을 포함하는 전체 콘텐츠 검색은 현재 제공하지 않는다.

### 말단 Topic

- 모든 Topic은 클릭할 수 있어야 한다.
- Child Scene이 없는 Topic은 URL과 Camera를 바꾸지 않고 Explanation Panel에서 설명을 연다.
- 별도 설명이 없으면 빈 화면 대신 설명이 없음을 알린다.

## 설명과 퀴즈

- Explanation Panel은 Scene 설명, Topic 설명과 퀴즈를 보여준다.
- 긴 설명은 지도와 별도로 스크롤할 수 있어야 한다.
- 사용자는 Panel을 접거나 같은 화면 안에서 읽기 모드로 넓힐 수 있다.
- 짧은 Preview는 보조 정보이며 핵심 설명을 대신하지 않는다.
- 독립적인 내부 구조나 별도 흐름이 필요한 내용은 Child Scene으로 분리한다.
- 현재 Scene의 관계, 예시와 주의사항은 불필요하게 다른 Scene으로 나누지 않는다.
- 퀴즈는 질문과 답변으로 구성하며 사용자가 정답을 직접 열어 확인한다.
- 퀴즈가 없으면 준비된 퀴즈가 없다고 알린다.
- 점수, 진도와 결과 이력은 저장하지 않는다.

## 콘텐츠 요구사항

### Scene과 흐름

- Scene은 제목, 요약, Topic과 Edge를 가진다.
- Scene 깊이에는 고정된 최댓값을 두지 않는다.
- Edge는 데이터 이동이나 실행 순서처럼 현재 Scene의 흐름을 보여준다.
- 서로 다른 관계를 같은 모양의 Edge로 무분별하게 표현하지 않는다.
- Edge의 의미가 중요하면 짧은 Label로 표시한다.
- Scene Area는 Topic의 시각적 소속만 표현하며 클릭과 탐색 대상이 아니다.
- 콘텐츠 데이터에는 URL과 실제 화면 좌표처럼 계산할 수 있는 값을 중복 저장하지 않는다.

### 설명

- 설명 분량에는 고정된 제한을 두지 않는다.
- 한 문서에 모든 사실을 나열하지 않고 학습 순서에 맞게 구조화한다.
- 사실은 공식 문서와 1차 자료를 우선 확인한다.
- 일반적인 구조와 특정 제품의 구현을 구분한다.
- 불확실하거나 구현에 따라 다른 내용을 단정하지 않는다.
- 정확한 작성 방식은 [콘텐츠 작성 가이드](./CONTENT_GUIDE.md)를 따른다.

### 검증

- 콘텐츠와 화면 코드는 분리한다.
- Scene을 추가할 때 탐색 엔진 코드를 수정하지 않아야 한다.
- 게시 전에 필수 값, 중복 ID, 잘못된 참조와 Child Scene 순환을 확인한다.
- Root Scene에서 도달할 수 없는 Scene은 Explorer와 URL에 노출하지 않는다.
- Markdown의 임의 HTML과 JavaScript를 실행하지 않는다.

## 품질 요구사항

### 접근성

- 모든 Topic과 퀴즈를 키보드로 조작할 수 있어야 한다.
- Scene 이동 후 포커스 위치와 화면 변화를 알 수 있어야 한다.
- 상태와 Edge 의미를 색상만으로 전달하지 않는다.
- 그림을 이해할 수 있는 텍스트 설명을 제공한다.
- 운영체제의 동작 감소 설정과 브라우저 확대를 존중한다.

### 성능과 안정성

- 첫 화면에서 모든 Scene과 설명을 한꺼번에 불러오지 않는다.
- 화면 밖의 Scene과 불필요한 애니메이션을 렌더링하지 않는다.
- 선택 가능성이 높은 Scene은 현재 탐색을 바꾸지 않고 미리 준비할 수 있다.
- 이미 불러온 콘텐츠는 재사용하고 실패한 요청은 다시 시도할 수 있어야 한다.
- 로딩에 실패해도 현재 Scene을 유지하고 복구 방법을 제공한다.

### 지원 환경과 보안

- 데스크톱의 최신 주요 브라우저를 우선 지원한다.
- 작은 화면에서도 콘텐츠가 깨지지 않아야 하지만 모바일 전용 최적화는 요구하지 않는다.
- 현재 제품은 개인정보를 수집하지 않는다.
- 외부 링크와 미디어는 안전하게 처리한다.

## 완료 조건

- 사용자가 Root Scene을 보고 여러 단계의 Child Scene으로 연속 진입할 수 있다.
- Scene 이동과 복귀 과정에서 공간적 관계와 이전 위치를 이해할 수 있다.
- Scene URL을 공유하거나 새로고침해도 같은 위치가 열린다.
- 말단 Topic에서 설명 또는 설명 없음 상태를 확인할 수 있다.
- 지도와 긴 설명을 동시에 보고 각각 탐색하고 스크롤할 수 있다.
- 새 Scene을 추가해도 탐색 엔진 코드를 변경하지 않는다.
- 잘못된 콘텐츠 참조와 Child Scene 순환이 게시 전에 탐지된다.
- 키보드와 동작 감소 설정으로 핵심 탐색 경로를 사용할 수 있다.
- Topic별 퀴즈의 답변을 확인할 수 있으며 결과는 저장되지 않는다.
