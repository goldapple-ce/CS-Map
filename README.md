# CS Zoom Map 프로젝트 시작 패키지

이 패키지는 AI 개발 도구에 프로젝트 구현을 맡기기 위한 기준 문서 모음이다. 처음부터 모든 문서를 사용할 필요는 없다.

## 핵심 문서 5개

| 문서 | 역할 |
|---|---|
| `AGENTS.md` | AI가 프로젝트에서 항상 지켜야 할 짧은 규칙 |
| `REQUIREMENTS.md` | 제품·기능·비기능 요구사항의 기준 문서 |
| `TECHNICAL_DESIGN.md` | 기술 스택, 콘텐츠 모델, 렌더링 및 URL 설계 |
| `PLAN.md` | 현재 위치와 다음 작업을 보여주는 8단계 진행표 |
| `README.md` | 시작 순서와 AI 사용 방법 |

초기 구현에는 위 다섯 개면 충분하다.

## 필요할 때만 추가하는 참고 문서

| 문서 | 사용할 시점 |
|---|---|
| `CONTENT_GUIDE.md` | 실제 학습 콘텐츠를 대량 작성하기 시작할 때 |
| `SCENE_MAP.md` | 구글 검색 장면의 상세 범위를 정할 때 |
| `AI_HANDOFF_PROMPT.md` | 더 엄격한 AI 요청 템플릿이 필요할 때 |
| `ACCEPTANCE_CHECKLIST.md` | MVP 완성 직전 전체 검수할 때 |
| `IMPLEMENTATION_PLAN.md` | AI 작업을 더 작게 나눌 필요가 있을 때 보는 상세 참고 계획 |

## 권장 사용 순서

1. 새 Git 저장소의 루트에 핵심 문서 5개를 복사한다.
2. AI에게 `AGENTS.md`, `REQUIREMENTS.md`, `TECHNICAL_DESIGN.md`, `PLAN.md`를 순서대로 읽게 한다.
3. `PLAN.md`에서 `▶ 현재`로 표시된 단계만 맡긴다.
4. AI는 작업과 테스트 및 진행표 갱신까지만 하고 Git 커밋은 사용자가 직접 한다.
5. 각 단계의 “눈으로 확인할 결과”를 확인한 뒤 사용자가 커밋한다.
6. 실제 콘텐츠를 확장하기 시작할 때 선택적으로 `CONTENT_GUIDE.md`와 `SCENE_MAP.md`를 추가한다.

## AI에게 맡길 때의 원칙

- 한 번에 전체 서비스를 구현시키지 않는다.
- 한 요청은 `PLAN.md`의 현재 단계 하나만 다룬다.
- AI가 다음 단계를 임의로 선행하지 못하게 한다.
- 기능을 추가하기 전에 현재 단계의 테스트와 변경 파일을 보고받는다.
- AI는 Git 커밋·push·tag를 실행하지 않는다.
- 요구사항과 충돌하면 구현 편의보다 `REQUIREMENTS.md`를 우선한다.
- 범위 밖 아이디어는 구현하지 말고 별도 제안으로만 기록하게 한다.
- UI는 Tailwind CSS와 shadcn/ui를 사용하고 별도 CSS 체계를 추가하지 않는다.

## 최초 목표

첫 번째 수직 프로토타입은 다음 한 경로만 완성한다.

```text
구글 검색 → 네트워크 → DNS → UDP 질의 → Socket/Kernel
```

이 경로에서 다음을 먼저 검증한다.

- 클릭한 대상이 확대되어 내부 장면으로 이어지는가?
- 새 페이지처럼 끊기지 않는가?
- 뒤로 갔을 때 이전 장면과 읽던 설명 위치가 복원되는가?
- 지도와 긴 설명을 동시에 사용할 수 있는가?
- 새로운 하위 장면을 데이터만으로 추가할 수 있는가?
